# 虛擬設備控制 V1

日期：2026-10-10 · 版本：0.1.0

這是一個可操作、可重現的視覺控制實驗。控制器從真正渲染的相機影像中觀測兩個彩色標記，試動未知馬達通道，建立局部映射，閉迴圈移到指定目標。過程由線上演算法決定，沒有預錄軌跡。

## 開始使用

1. 使用電腦上的 Chrome 或 Edge 開啟 `virtual-device-v1.html`。可以直接雙擊檔案，不需安裝套件、API 金鑰或連上網路。
2. 按「開始自主學習」。青色是末端，洋紅色是目標；先觀察小幅試動，再看誤差是否下降。
3. 到達後按「下一個目標並開始」，測試它使用已學映射處理新目標。
4. 按「改變相機」或「反轉馬達」，再開始控制。已到達時，挑戰按鈕會同時抽取新目標，確保需要再次移動。執行中改變條件則沿用當前任務。
5. 改變「設備種子」後按重建，建立不同連桿長度、通道對應、方向、增益與相機參數的設備，並清空控制器映射。
6. 按「執行驗證測試」跑 4 個固定種子、每個 4 種情境，共 16 次測試。按「匯出紀錄」取得 JSON。

可以在畫面上直接點選目標；任意點可能不可達。「抽取新的可達目標」則由設備端產生可達目標。遮住末端標記後，控制器在下一次觀測停止；恢復標記後重新開始即可。每次最多 180 個動作，容許影像誤差為 7 px。

若瀏覽器預覽區不執行互動內容，先下載 HTML 再用桌面瀏覽器開啟。也可以在此資料夾執行 `python -m http.server 8000 --bind 127.0.0.1`，瀏覽 `http://127.0.0.1:8000/virtual-device-v1.html`。

## 第一版驗證什麼

驗證第一項能力的受限版本：已有兩個可以小幅驅動的通道，但不知道其方向、對應關節、增益、機構長度與相機轉換，仍能透過試動和影像建立局部控制能力。

系統仍預先知道：通道數量為 2、允許的指令幅度、標記顏色、觀測格式、停止預算與到達門檻。設備端已有基礎運動規則與限幅。這不是從完全無協定的硬體自動發現通訊，也不代表所有未知設備都可控制。

這版使用可檢查的傳統視覺與自適應控制演算法，沒有呼叫 LLM、沒有模型訓練服務，也尚未加入「物件應放哪裡」的整理代理。

## 架構與資料邊界

| 模組 | 職責 | 能看見的資料 |
| --- | --- | --- |
| `src/plant.js` | 虛擬二連桿、渲染相機、動作限制、目標設定 | 真實幾何、關節、相機與指令 |
| `src/controller.js` | 標記辨識、試動學習、控制與停止判斷 | RGBA 像素、影像大小、上次實際允許的通道指令 |
| `src/app.js` | 操作介面、影像傳輸、事件紀錄、批次評估 | 設備與控制器結果；評估用真值 |

控制器在獨立 Web Worker 中執行，無法直接讀取主頁的設備實例、DOM 或評估資訊。每次控制訊息只有 `width`、`height`、`pixels`、`applied` 四個欄位。相機影像由 Canvas 實際渲染後讀回像素，控制器自行分割顏色並計算質心，沒有把精確端點座標或逆運動學答案傳入。

`diagnostics()` 是設備提供給評估器的真值。它會進入匯出的評估區，**不會傳入控制器**。目前隔離目的是確保實驗資料邊界，並非對惡意程式的安全沙箱保證。

Web Worker 與設備目前位於同一個瀏覽器，透過訊息交換；還沒有遠端電腦服務或實體設備連線。日後可以替換傳輸和設備介面，但仍須處理延遲、時間戳、斷線、限位與實測校正。

## 控制方法

1. 以已知顏色分割影像，估計末端與目標的像素位置。
2. 對兩個通道依序施加正反向小幅試動，共六個動作，估計局部 2×2 Jacobian。
3. 由像素誤差與估計映射計算阻尼最小平方控制量，並限制每次動作幅度。
4. 以新影像檢查實際位移，用 Broyden 更新追蹤局部非線性。
5. 位移與預測差異太大、目標在影像中改變或進展停滯時，重新試動估計。
6. 到達門檻內回報成功；標記消失停止；預算用盡回報失敗。

映射是局部近似，沒有全域路徑規劃、避障、接觸或抓取模型。白色虛線圈是模型對下一個觀測位置的預測，青色標記來自相機影像；兩者可能不同。

## 已完成的驗證

桌面 Chrome、實際 Canvas 渲染與 Worker 的整合測試：

| 情境 | 結果 |
| --- | --- |
| 20 個設備種子 × 初次學習 | 20 / 20 成功 |
| 20 個設備種子 × 新目標 | 20 / 20 成功 |
| 20 個設備種子 × 相機變動 | 20 / 20 成功 |
| 20 個設備種子 × 馬達反向 | 20 / 20 成功 |
| 控制期間變更相機、反轉馬達 | 2 / 2 恢復並到達 |
| 遮蔽末端標記 | 無後續動作，回報標記遺失 |
| 可見但不可達的目標 | 180 次動作後停止並回報失敗 |

80 次試驗平均 13.15 個動作，最多 34 個；成功時評估真值的最大誤差為 6.92 px 以下。這是本次固定種子與可達目標抽樣的結果，不是任意場景的成功率保證。各情境在同一個設備上順序測試，初次學習後保留映射；不是每次都從零重新學習。

另外檢查 390 px 手機排版、紀錄匯出、控制訊息欄位、無外部網路請求與 JavaScript 錯誤。完整結果在 `validation/benchmark-results.json` 與 `validation/validation-summary.json`。`tests/controller-smoke.cjs` 是獨立簡化影像測試，與整合測試分開計算。

## 重新建置與測試

修改 `src/` 後執行：

```powershell
python build.py
```

日常使用 HTML 不需 Python 或 Node。開發驗證另外需要 Python 的 Playwright 套件與已安裝的 Chrome；測試預設採用 Windows Chrome 路徑，也可設定 `CHROME_PATH`：

```powershell
python -m pip install playwright
python tests/validate_browser.py
node tests/controller-smoke.cjs
```

## 後續開發順序

1. 擴充觀測噪聲、訊息延遲、漏步與標記短暫遮蔽，加入固定校正策略作為比較基準。
2. 把相同的影像／動作介面接到獨立設備服務，再測同機與遠端傳輸。
3. 根據實際手臂或列印機的介面，接上真實相機與基本驅動，重新驗證。
4. 持續同步實體量測並校正虛擬模型，才發展為相應設備的數位孿生。
5. 在可靠的移動能力上加入物件辨識、整理規則、抓取與任務代理。

目前的幾何模擬沒有重力、慣性、摩擦、馬達回差、碰撞、透視深度或接觸。純粹的虛擬模型也尚不構成實體設備的數位孿生。
