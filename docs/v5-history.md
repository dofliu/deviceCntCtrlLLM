# DOFLAB 陌生設備接手與取放實驗 V5.3

## 先開始操作

直接用 Chrome 或 Edge 開啟 `unknown-device-v5.3.html`，選「開始完整測試」。預設為離線規則代理，從未連線開始，執行設備辨識假設、介面與手冊查核、握手、產生與測試驅動，再學習 XY 控制，將橘色物件移到藍色 B 區。介面採固定視窗與分頁；程式碼、完整紀錄可在各分頁內捲動。

要使用真正 Claude，從頁面下載完整原始碼並解壓縮，執行 `python build.py`，再執行 `python claude_bridge.py` 或按兩下 `start-lab.cmd`。用瀏覽器開啟 http://127.0.0.1:8766/ ，在設定頁選 Claude，取得帳號可用模型後開始。詳見 `docs/claude.md`。

要改用 Gemini，從頁面「設定」下載完整原始碼並解壓縮，按兩下 **`start-gemini.cmd`**。它會建立 HTML，讀取 **`gemini_api_key`**，並開啟 http://127.0.0.1:8767/?agent=gemini 。若本機找不到同名環境變數，終端機會以隱藏輸入方式請你輸入金鑰，只保留在本次程序記憶體。進入設定頁後按「取得可用模型」，選定模型，再按「套用並從零開始」及「開始完整實驗」。詳見 `docs/gemini.md`。

也可直接開啟 HTML，在「設定 → 決策代理」選 Gemini，連接方式改成「直接連線」，在密碼欄手動輸入金鑰後取得模型。金鑰不寫入檔案、瀏覽器儲存或匯出紀錄；切換供應商會清除輸入的金鑰及模型，需重新設定。

橋接預設讀取使用者已授權的 `ANTHROPIC_API_KEY`，Windows 支援程序、使用者及系統環境變數。金鑰留在本機 Python 程序，不寫進 HTML 或下載的紀錄。若要改用先前授權的名稱，明確指定 `--key-env ANTHROPIC_API_KEY_Extra`；不自動猜測其他金鑰。

## 完整流程與成功定義

1. 從相機與標籤提出設備假設，保留不確定規格。
2. 取得模擬主機介面清單與設備通訊手冊，建立連線並實際握手。
3. 產生 JavaScript 編碼／解碼程式，在隔離環境編譯，通過不移動設備的測試。
4. 看影像、小幅試動，建立未知 XY 指令與位移的局部映射。
5. 對準橘色物件、下降、閉合、抬起，取得抓取的影像證據。
6. 攜帶物件到藍色 B 區、下降、放開，再讓夾爪離開。
7. 重新觀察物件留在 B 區及夾爪已分離；僅到達目標或收到指令回覆不算成功。

物件依實際模擬狀態附著、搬運與釋放，所有 XY、升降及夾爪命令都經過本次產生的驅動程式。離線模式採用手冊程式範本；Claude 與 Gemini 模式由模型回傳程式原始碼與工具決策。不暗中改用離線代理。

## V5.3：預期說明不再阻斷合法指令

使用者提供的 V5.2 實測紀錄顯示：`claude-haiku-5-5` 已完成連線與驅動測試，執行 5 次動作（3 次 XY probing、2 次升降／開爪），在接近物件階段停止。最後連續三次 `probe` 回覆都缺少 `expected`，觸發 `invalid-envelope`；兩次修正機會已使用，尚未抓取物件。整場 19 次模型請求，共 4 次拒絕；其中另一次發生在 `read_manual`。

`expected` 是供介面呈現的預期結果說明，不應因缺少這段文字就阻止後續指令檢查。V5.3 將它改成選填；缺少時記錄 `expectedProvided:false`、保留空字串，畫面顯示「模型未提供預期說明」，不代填成模型說過的內容。工具名稱、`args`、`reason` 與完整參數範圍仍須通過檢查。若模型有提供 `expected`，仍檢查型別、長度與空白內容。

舊報告在外層欄位檢查就拒絕，因此不能確認那三筆 `probe` 的動作參數原本是否合法。新版會繼續檢查實際參數，且取放成功仍須通過新影像驗證。此修正處理已確認的阻斷原因，不代表真實模型已完成取放。

V5.3 已通過 Claude 12 組、Gemini 13 組模擬 provider 檢查，以及 `tests/test_expected_contract.cjs` 的純 Node 整合檢查：合法試動缺少說明仍可提出，提案不動作，執行時僅動作一次；非法工具、參數、超出範圍與缺少必要欄位仍會被拒絕。這些測試沒有讀取金鑰、啟動瀏覽器或呼叫真正模型，不是原始失敗回覆的逐字重播，也不代表完整取放實測成功。

## 保留進度的有限次修正（V5.2 起）

模型回覆的工具、參數或格式不合法時，該次指令不會執行。介面會顯示具體拒絕原因，保留目前連線、已通過測試的驅動與校正進度，再把錯誤回饋給同一個模型，最多修正兩次。每次修正都另計一次模型請求，仍受整場請求上限約束；連續三次不合法就停止並保留紀錄。

這個處理僅適用於回覆檢查的 `INVALID_DECISION`、`INVALID_ARGUMENTS`、`INVALID_TOOL_RESPONSE`。金鑰、額度、網路與逾時等錯誤仍會停止；已送出的設備命令不會因這個機制重送。匯出紀錄包含經過篩選的拒絕原因與修正次數，不保存完整被拒絕的模型回覆。

下一次測試請使用新版 HTML，保留原本的 Claude 模型與 seed 42，從零開始，便於比較。若勾選「關鍵步驟暫停」，決策遭拒後會暫停供檢查，按下一步即可請模型修正。舊版匯出的 JSON 可供分析，不能匯入恢復執行；保留進度的修正適用於新版目前開啟的實驗。

更新既有本機橋接時，可把新版 `unknown-device-v5.3.html` 放到 `claude_bridge.py` 同一資料夾，關閉先前橋接後執行 `python claude_bridge.py --html unknown-device-v5.3.html --open-browser`，並確認頁面版本為 V5.3。也可從新版 HTML 下載完整原始碼，解壓到新資料夾後執行 `start-lab.cmd`；啟動器會先重新建置同一版本的介面。

V5.2 驗證紀錄：Claude 11 組、Gemini 12 組 provider mock 檢查通過；兩個供應商的修正請求預算測試通過，確認達上限不再送出請求。第一個完整故障注入案例在已校正後遇到兩次不合法回覆，修正後完成取放，42 次有效決策加 2 次拒絕回覆，共 44 次模擬請求，設備仍只執行 24 次動作。介面測試涵蓋 15 個分頁與畫面尺寸組合，通過修正、停止及回看檢查。

純 Node 的修正策略測試也已通過，直接驗證正式程式的三次拒絕上限、接受有效決策後重設次數、錯誤分類與診斷資料清理，無需瀏覽器或網路。測試結果見 `validation/recovery-policy-node.json`。

上述皆為本機測試，沒有新一輪真實模型成功證據。追加瀏覽器驗證的操作遭執行環境自動審查拒絕，理由為 Visual Studio 遙測可能傳出的內容未明確授權；未重跑被拒絕操作。完整故障注入套件只記錄已觀察到的一個通過案例，其餘七個列為未驗證，見 `validation/decision-recovery-workflow.json`。這不影響已完成的 provider、介面、預算及機械取放檢查結果。

## 實際專案的架構

HTML／CSS／JavaScript 適合作為操作與監看介面。原型將前端與模擬器打包成單一 HTML，方便直接開啟。接實體設備時，建議沿用介面，但由本機服務管理相機、裝置驅動、金鑰、命令限制及紀錄；操作介面透過 HTTP 或 WebSocket 與服務溝通。設備即時控制由控制器／韌體處理，語言模型選擇工具與規劃步驟。

可先用本版的 Python 服務作為連接起點，再把模擬傳輸介面逐一替換為明確型號設備的 Serial、TCP 等驅動。這不是把所有即時控制或通訊都塞進單一 HTML。

## 驗證範圍

本版是二連桿平面機構，加上已定義的升降與夾爪介面。XY 方向及增益需透過試動學習；Z 與夾爪的動作語意由手冊提供。物件使用已知顏色標記，抓取採簡化狀態與接近條件，沒有完整接觸力學、抓持力估測、任意形狀辨識或未知韌體自動建立能力。

取放步驟具有預先定義的先決條件；目前驗證受約束流程中的模型工具選擇與未知 XY 校正，尚未驗證模型自行發明任意整理策略。影像以簡化投影呈現提起位移，搬運時另外檢查物件與夾具的共同位移。

模擬 Serial/TCP 介面不會掃描或操作使用者的真實設備。前置手冊是內建模擬文件。Claude 與 Gemini 所見包含相機影像、手冊、通訊與已量測證據，不含模擬器內的真實連桿尺寸、關節角度、通道方向或物件附著狀態。

驗證結果保存在 `validation/`。離線、模擬 API 和真正 Claude 測試分開標示，單次成功不能代表跨設備泛化成功率。
